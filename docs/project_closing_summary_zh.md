# 毕设收尾总结

本文件整理项目收尾阶段形成的经验、教训和归档边界，便于后续复查、提交毕设系统或继续扩展实验。

## 归档边界

- `code/main/` 保存论文方法的主代码入口。
- `code/tools/` 保存图表生成、结果整理、验收材料处理等离线工具。
- `experiments/` 保存实验脚本和运行配置清单。
- `results/tables/` 保存可追溯的正式结果表。
- `results/figures/` 保存论文、答辩和展示使用的图件。
- `materials/` 保存最终论文、答辩材料、过程文档、质量检查和正式结题材料。
- `archives/` 保存大型原始结果包索引；文件主体放在 GitHub Release，避免仓库正文过重。

## 实验经验

1. 训练阶段奖励和测试阶段策略必须分开讲。奖励机制解释学习过程，正式测试只执行训练好的策略网络。
2. 主结果、补充结果和诊断结果要分层使用。续训、短距离失败和压力测试可以解释边界，但不能替代主评测。
3. 短距离 C1-C3 不应包装成优势。它揭示局部相似、探索偏移和直接匹配之间的边界。
4. xBD 口径必须说清楚：灾后搜索区域，目标仍使用灾前图像嵌入。
5. 消融实验应强调组合机制，而不是把每个因子都说成独立正收益。

## 材料整理经验

1. 首页 README 只放最终主线和高价值展示材料；来源、历史、边界和清单放进 `docs/`。
2. 图件按用途分层：论文图、答辩图、验收动图、奖励案例、展示图和原始大包索引分开保存。
3. 正式材料按功能归档，不按每次上传日期建新目录；日期只用于 manifest 和提交记录。
4. 大型素材包优先进入 Release 附件，仓库正文保留 README、manifest 和少量精选展示文件。
5. 每次补充材料都要记录来源路径、目标路径、文件大小和 SHA-256，避免重复上传和误删。

## 仓库维护经验

1. 上传前确认目标仓库和分支，避免把毕业设计材料传到参考项目或临时仓库。
2. 本地工作区存在大量未提交变动时，只提交本轮明确需要的路径。
3. GitHub 单文件限制要提前检查；PPT、ZIP、checkpoint 和原始数据包不适合直接放入仓库正文。
4. 凭据只从安全环境变量读取，不写入 remote URL、README、脚本或连续性文档。
5. 仓库结构稳定后，新增材料应归入既有目录，并同步更新索引，而不是继续新增日期包目录。

## 后续建议

- 毕设系统附件优先使用 `materials/` 中的正式材料和 `submission_packages/` 中已准备的干净代码压缩包。
- 继续实验时优先复用 `experiments/` 中的 manifest，避免新结果无法对应到 checkpoint 和数据口径。
- 对外展示优先使用 README 首页和 `results/figures/showcase/`，完整追溯再进入 `docs/`、`results/reports/` 和 `archives/`。
